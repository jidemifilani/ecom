Overview

Ecom is a multipurpose, market-adaptable full-stack e-commerce platform with an enterprise admin back-office and a consumer storefront. It is a production-grade, single-repo Next.js application.

Tech stack

Frontend
  • Next.js 16.4.5 — App Router, RSC
  • React 19.3.1
  • TypeScript 5.9.3 strict mode
  • Tailwind CSS 4.3.4
  • Radix UI primitives (12 packages)
  • React Hook Form + Zod validation
  • Recharts for dashboard charts
  • Lucide React icons
  • Sonner toasts
Backend
  • Next.js Route Handlers (API)
  • Prisma 7.10.1 + @prisma/adapter-pg
  • PostgreSQL 17 (local Docker)
  • Neon serverless Postgres (production)
  • bcryptjs for password hashing
  • jose for JWT (password-reset tokens)
  • nodemailer for transactional email
  • DB-backed opaque sessions
Security
  • CSRF: Origin/Host check + double-submit cookie ecom_csrf
  • Rate limiting (DB-backed counters)
  • Login lockout after 5 attempts
  • RBAC: 55 permissions, authority levels
  • Separate staff / shopper session cookies
  • Entra ID SSO (optional, feature-flagged)
  • Zod server-env validation at boot
  • Audit log on every mutation
Tooling & testing
  • Vitest (unit + component + integration)
  • Playwright E2E on port 3100
  • ESLint + Prettier
  • Docker Compose (local Postgres)
  • Vercel CLI for deployment

RBAC & permissions

Permissions follow the pattern resource.action. Each staff user has one or more roles; roles carry a permission set and an authority level (higher levels cannot be managed by lower levels).

Roles

super_admin55 permsAll permissions, authority level 100. Created by seed.
admin52 permsEverything except system settings and audit export.
manager40 permsCatalog, orders, customers, inventory, discounts, reports.
staff12 permsRead-only catalog + orders + inventory.

Auth system

Staff auth (admin)
  • Cookie: ecom_session (HttpOnly, Secure, SameSite=Lax)
  • Sessions stored in Session DB table
  • Idle timeout: 30 days (configurable)
  • Absolute timeout: 90 days (configurable)
  • Lockout after 5 failed attempts (900s)
  • Password reset via signed JWT emailed link
  • Entra ID SSO (optional, AUTH_ENTRA_ENABLED=true)
  • Force password change flag on first login
Shopper auth (storefront)
  • Cookie: ecom_shop_session
  • Same DB-backed session mechanism
  • Register, login, forgot / reset password
  • Guest cart merges on login
  • Separate from staff sessions entirely
CSRF protection
  • Double-submit cookie: ecom_csrf
  • Origin header checked against APP_URL
  • Falls back to Host-derived origin
  • Applied to all mutating API routes
Password policy
  • Minimum 12 characters (configurable)
  • bcrypt cost factor 12 (configurable)
  • No common-password check (can add)

Dev workflow

Common commands
npm run dev              # Next.js dev server :3000
npm run build            # prisma generate + next build
npm run typecheck        # tsc --noEmit
npm run lint             # ESLint
npm run test             # Vitest (all projects)
npm run test:unit        # unit tests only
npm run test:integration # integration tests only
npm run e2e              # Playwright (port 3100)
npm run db:migrate       # run pending migrations
npm run db:seed          # seed demo data
npm run db:studio        # Prisma Studio
npm run docker:up        # start local Postgres
Local setup
  • Node ≥ 20.11.0
  • Docker Desktop for local Postgres
  • Copy .env.example → .env.local
  • Set AUTH_SECRET (openssl rand -base64 32)
  • Run npm run docker:up
  • Run npm run db:migrate
  • Run npm run db:seed
  • Run npm run dev
E2E test setup
  • Set APP_URL=http://localhost:3100 in .env.test
  • Run npm run test:db:setup (separate test DB)
  • Start dev server on port 3100
  • Run npm run e2e
  • Coverage: admin login, bad-creds, form validation
  • Coverage: storefront browse, add-to-cart, checkout flow
One-off DB scripts
  • npx tsx prisma/update-images.ts — set all 24 product photos to Unsplash URLs
  • npx tsx prisma/fix-broken-images.ts — patch expired photo IDs
  • Both use DATABASE_URL_UNPOOLED from .env.local

Deployment

Vercel (production)
  • Project: jidemifilanis-projects/ecom
  • Live URL: ecom-iota-beryl.vercel.app
  • GitHub: jidemifilani/ecom (public)
  • Output mode: standalone
  • Deployment protection: disabled (public)
  • Command: vercel --prod --yes
Neon database
  • Resource: ecom-db (free tier, free_v3)
  • Linked to Vercel project via integration
  • Pooled URL: POSTGRES_URL / DATABASE_URL
  • Direct URL: DATABASE_URL_UNPOOLED
  • Migrations run via db:migrate:deploy
Required Vercel env vars
  • DATABASE_URL — set by Neon integration
  • DATABASE_URL_UNPOOLED — set by Neon integration
  • AUTH_SECRET — set manually (≥32 chars)
  • APP_URL — set to https://ecom-iota-beryl.vercel.app
  • SMTP vars — optional (email logs to console if unset)
Build notes
  • Build runs prisma generate then next build
  • NEXT_PHASE=phase-production-build set during build
  • Production-only env checks are skipped during build phase
  • Prisma client output: src/generated/prisma/
  • serverExternalPackages: @prisma/client, pg, bcryptjs
